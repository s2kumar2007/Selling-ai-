# Architecture note (1 page)

**Principle: code decides every number.** The language model never invents a price, a stock count or a policy.

```
buyer message ─► 1 Parser (untrusted data → fields + claim tags)
              ─► 2 Kernel (floor, curve, accept, bundle, stock)  ◄─ logged tools: get_price, check_stock,
              │                                                      compute_floor, compute_offer, accept_deal
              ─► 3+4 One LLM call (Groq): picks a move from the kernel's menu, writes wording with placeholders
              ─► 5a Local pre-check (store.csv + tool log)  ─► 5b Rezolve TraceWare verdict ─► send on PASS
```

| Layer | What it does | Where |
|---|---|---|
| 1 Parser | Extracts intent, lines, offered price; tags competitor quotes, budgets, authority, policy overrides, injection. Buyer text never reaches the model as instructions. | `seller_agent/parser.py` |
| 2 Kernel | floor = max(cost/(1−min_margin), list×(1−max_discount)); offer(t) = open − (open−floor)·(t/H)^(1/β), β<1; never up, never below floor; stock every turn; final offer in the last rounds; walk away if no deal; bundle option; opponent concession rate from numbers only. | `seller_agent/kernel.py`, `floor.py` |
| 3+4 Tactician | One call per turn, strict JSON `{move, message}`; digits, currency and percentages rejected; placeholders filled from verified facts; templates for trivial turns and as the fallback. | `seller_agent/tactician.py`, `templates.py` |
| Tools | Five logged calls; the log is the ground truth for both gates. | `tools/toolbox.py` |
| 5 Gate | Local invariants: quoted price came from `compute_offer`, price ≥ floor, stock claims match `check_stock`, no scarcity or pressure wording, no fees, no competitor matching, no deal/order wording before a recorded `accept_deal`. Then TraceWare. After 2 failures a safe template is sent. If TraceWare is unreachable the local check still has to pass and the outage is logged; an auth error is never read as PASS. | `seller_agent/gate.py`, `traceware.py` |

**Rezolve Labs capabilities used**
1. **TraceWare commerce claim verification** (`POST /traceware/verify`): each outgoing message is verified against recorded `add_to_basket` actions; the decision (PASS / WARN / REGENERATE / BLOCK) gates the send. `GET /traceware/checks` was read to confirm the enabled checks (`cart_contents`, `order_completed`); the per-message verdict and evidence appear in the demo panel.
2. **Managed knowledge retrieval:** policy text, product descriptions (no prices or stock), FAQ and the agent card are generated by `scripts/build_kb_docs.py` for upload.

Not used: voice, images, AEO, watermarking. Agent builder was evaluated as an option; the kernel stays in our own code.

**Division of labour.** TraceWare's configured checks cover cart and order claims, and profile changes are operator-managed. Price-versus-floor, price source, stock and wording rules are therefore enforced by our local pre-check, and TraceWare is the independent second check on what the seller says it did.

**Robustness.** Fake quotes, budgets, "SYSTEM" or "manager" messages and injected lines change nothing: the kernel reads only structured numbers. Extra, out-of-stock, over-stock or ₹1 lines are never accepted. Twin buyers receive the same offers.

**Cost and scale.** Kernel ≈ 0.2 ms per turn. At most one LLM call per turn; token use and TraceWare credits are logged per negotiation. Exponential backoff on 429, a request limiter, caching, and template fallback keep it running under rate limits.
